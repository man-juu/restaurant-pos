# 09. Decisions and Open Questions

## 1. Decision log (ADRs)

Status: **Accepted** (agreed), **Proposed** (my recommendation, needs your confirmation), **Superseded**.

| ID | Decision | Status | Rationale | Alternatives considered |
| --- | --- | --- | --- | --- |
| ADR-001 | Modular monolith with enforced module boundaries | Accepted | One developer, one small server, atomic cross-module postings | Microservices (too much operations work) |
| ADR-002 | One shared database and schema, `tenant_id` everywhere, PostgreSQL row-level security with FORCE | Accepted | Cheapest to run and migrate; database-enforced isolation | Schema per tenant, database per tenant (more memory and migration cost; kept as a later option for special tenants) |
| ADR-003 | Server-side sessions in httpOnly cookies, CSRF token, Argon2id, TOTP | Proposed | Easy revocation, no tokens in browser storage | JWT access plus refresh tokens |
| ADR-004 | Stock and finance ledgers are append-only; corrections are reversals | Accepted | Auditability and reproducible history | Editable balances |
| ADR-005 | No Redis at launch; Postgres-backed job queue and caching in tables | Proposed | Saves memory and one service on a small VPS | Redis with a worker library |
| ADR-006 | Async SQLAlchemy 2 with asyncpg | Proposed | Fits FastAPI; good concurrency per worker | Sync SQLAlchemy (simpler debugging) |
| ADR-007 | Job library: evaluate Procrastinate against a minimal in-house `SKIP LOCKED` queue in Phase 0 | Proposed | Decide with a spike, not by guess | Celery, arq (need Redis) |
| ADR-008 | Moving average costing, calculated per outlet | Accepted | Simple and widely understood; confirmed by you (Q-002) | FIFO layers, latest cost, tenant-wide average |
| ADR-009 | FEFO batch consumption with batch and expiry on all stocked items | Accepted | Frozen and perishable goods | FIFO, no batches |
| ADR-010 | Money as integer minor units; quantities `numeric(18,4)`; unit costs `numeric(18,6)` | Accepted | No floating point errors | Decimal everywhere |
| ADR-011 | Installable PWA for all devices; no native apps | Accepted | One codebase for desktop, tablet, phone | Native or hybrid apps |
| ADR-012 | In-transaction events for stock and finance postings; outbox for everything else | Accepted | Money and stock can never disagree; slow work stays out of requests | All asynchronous |
| ADR-013 | Manual sales entry first; delivery-platform integration only via approved partner later | Accepted | API access is gated by the platforms; scraping is fragile and against terms | Scraping, unofficial APIs |

| ADR-015 | Host on Biznet Gio NEO Lite MS 4.2 (4 GB) with Cloudflare free in front | Proposed | Indonesian data center, prepaid balance without a card, low cost | Hostinger KVM 2, IDCloudHost |
| ADR-016 | Tax, service charge, rounding and payment methods are tenant configuration | Accepted | Rates vary by region and change | Hard-coded Indonesian rules |
| ADR-017 | UUIDv7 primary keys generated by the server | Proposed | Index-friendly, no guessable sequences | Serial integers, UUIDv4 |
| ADR-018 | Module switching through `tenant_modules` plus a server-side dependency guard | Accepted | UI hiding is not security | UI-only toggles |
| ADR-019 | AI is an optional module, never in core logic, never fed tenant or customer data | Accepted | Free tiers may train on data; reliability not guaranteed | AI-driven forecasting |
| ADR-020 | English and Indonesian at launch with i18next; business content translatable per language | Accepted | Local-first, extensible | Single language |
| ADR-021 | Finance posting rules are configurable per tenant and enabling finance requires a start date | Proposed | Avoids retroactive journaling mistakes | Always-on accounting |

## 3. Assumptions

1. First tenant is yours; real use starts on the cloud kitchen with 5 to 7 outlets.
2. The first release needs internet at every outlet.
3. Tenants are small to mid-size; a single VPS is enough until measured otherwise.
4. Staff are comfortable with a touch interface but not with technical terms; UI language is plain.
5. An accountant reviews financial outputs before tax filing.
